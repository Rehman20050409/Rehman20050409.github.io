The login limit that an attacker could switch off

Split · November 2026

Split makes you wait 15 minutes after ten wrong passwords. I counted wrong tries per visitor address and email together, so that one person's wrong guesses could not lock anyone else out. Behind a hosting provider the visitor's address arrives in a header called X-Forwarded-For, so that is what the server read.

The problem is that the visitor can write that header themselves. I tested it against the live site: twelve wrong tries, each claiming a different address, and every one was let through. Without the fake header, the eleventh was blocked. The limit only worked on people who weren't trying to get round it.

The fix deleted code. Wrong tries are now counted per email and nothing else, and the same test against the live site stops at ten. It has a cost: someone who knows your email can lock you out for fifteen minutes at a time. I think that is the right trade, but it is a trade, and I wrote it down in the code where the next person will see it.

What I took from it: a security feature is not finished when it works for honest users. It is finished when you have tried to beat it yourself.

Parsing a language where calls have no brackets

Turtle · November 2026

In Turtle you write side 300 4, not side(300, 4). It reads nicely, but it leaves the parser with a question it cannot answer by looking at the line: where do the arguments stop? side 300 4 right 120 is two commands, and the only way to know that is to know side takes exactly two values.

It gets worse when a command calls itself, or is called above the place it is defined, because the parser reaches the call before it has seen the definition. My fix was a quick first pass over the whole program that only looks for definitions and counts their parameters. The real parse then starts already knowing how many values every command wants.

The other thing I had to plan for is that programs come from a text box, and people will write loops that never end. The interpreter counts its steps and its depth and stops with a normal error message, with a line number, instead of freezing the page.

One bug is still open: a drawing with tens of thousands of lines can fail without any message, because of how the page works out the drawing's size. The language is fine; the page around it is not. It is next on my list.

My own test file only proved what I already believed

Scratch Reader · November 2026

Scratch Reader opens a Scratch project and shows its blocks as code. I built it against a sample project I wrote by hand in Scratch's file format, and every test passed. That felt like done.

Then I ran it on 26 projects from the Scratch team's own test set. It read 23. The three that failed were zipped one folder deep, which my reader had never considered, because my sample was not. The same run showed a whole family of blocks coming out in a clumsy fallback form, and one block printing its name in quotes when it should not.

None of those were hard to fix. The point is that I could not have found them with my own sample, because I made the sample from the same understanding I wrote the code from. Any gap in one was a gap in the other.

The part that did hold up was the fallback: a block the reader has never heard of still prints as its name and inputs. Not pretty, but it meant unfamiliar projects produced readable output and never a crash.

Designing around sixty requests an hour

Repo Time-lapse · November 2026

Repo Time-lapse shows a GitHub project growing over time. GitHub allows 60 requests an hour to visitors who are not signed in, and a project can have thousands of commits, so asking about each one was never possible. The limit became the design.

The page picks ten moments spread from the first commit to the latest. Commits arrive a hundred to a page, newest first, and the first response says how many pages exist, so the page fetches only the ones holding a moment it wants and never the same one twice. Each moment then costs one more request for its list of files. A typical project needs about twenty requests.

The drawing had its own problem. If each moment were laid out separately, every file would jump to a new position whenever time moved. So every file that ever existed is placed once, in one shared layout, and files only fade in and out.

A test also caught something I had not thought about: the page accepted ../etc/passwd as a repository name. It was harmless here, but it is exactly the sort of input I should refuse on purpose and not by luck.
